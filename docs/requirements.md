# 需求说明

## 角色与范围

- **报修人**：查看设备清单中的设备信息，选择设备并提交非空故障描述，生成待处理工单。
- **维修人员**：查看设备信息，将工单从“待处理”推进到“处理中”，再从“处理中”推进到“已完成”。
- **范围**：仅分析查看设备、提交报修和更新工单状态三项功能；不实现网页、数据库、登录、真实硬件通信或完整报修系统。设备数据取自 `data/devices.csv`。

## FR-01 查看设备信息

- **角色**：报修人、维修人员。
- **前提**：设备清单可用。
- **输入**：设备编号 `deviceId`。
- **行为与正常结果**：系统按编号查找设备，返回设备编号、名称和位置。
- **异常结果**：当指定编号不存在时，系统给出“设备不存在”的明确提示，不返回其他设备信息。
- **验收方法**：输入 `DEV-001`，应显示“温湿度传感器 / A101教室”；输入 `DEV-999`，应提示设备不存在。

## FR-02 提交报修

- **角色**：报修人。
- **前提与输入**：报修人先从设备清单中选择一个设备，再填写非空故障描述。
- **正常结果**：系统创建工单，保存设备编号和故障描述，工单初始状态为 `PENDING`（待处理）。
- **异常结果**：未选择清单内设备、设备编号不存在或故障描述为空时，不创建工单并提示补全信息。
- **验收方法**：选择 `DEV-002` 并填写故障描述，应生成状态为 `PENDING` 的工单；故障描述为空时不得生成工单。

## FR-03 更新工单状态

- **角色**：维修人员。
- **允许的转换**：`PENDING → PROCESSING`（开始维修）、`PROCESSING → COMPLETED`（完成维修）。
- **拒绝的转换**：`PENDING → COMPLETED`、`COMPLETED → PROCESSING`、同状态转换以及其他所有组合。
- **正常与异常结果**：合法转换成功并更新状态；非法转换被拒绝，原状态保持不变。`COMPLETED` 为本次实验终态。
- **验收方法**：运行 `src/python/test_status_rule.py`，固定 4 项测试应全部通过，退出码为 0。

## 状态与程序值对应

| 中文状态 | 程序固定值 |
| --- | --- |
| 待处理 | `PENDING` |
| 处理中 | `PROCESSING` |
| 已完成 | `COMPLETED` |

## 已确认的实验规则

新工单为 `PENDING`，仅允许 `PENDING → PROCESSING`、`PROCESSING → COMPLETED`。其他转换一律拒绝。本实验只实现状态判断函数，不实现上述需求的完整软件界面。
